Customer API · V1

客户 API 文档

面向白名单客户的图片生成接口 · 类 OpenAI 风格 · 异步任务

01概述

  • 采用 Bearer Token 鉴权,异步创建任务后轮询查询结果。
  • 异步模型:创建任务立即返回 202,再用 poll_url 轮询,直到 status 变为 succeeded 或 failed。
  • 每张图固定计费 20 credits——创建时冻结,成功后结算,失败或超时自动退回。
  • 比例三选一:1:1、2:3、3:2。
  • API Key、额度由对接的管理员发放与充值,无自助注册。

02鉴权

所有 /v1/* 接口都需在请求头携带 API Key:

Authorization: Bearer gim_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Key 以 gim_ 开头,由管理员发放,明文仅在创建时出示一次,请妥善保存。

03创建生成任务

POST /v1/images/generations

请求体

{
  "prompt": "a cozy cabin in the snow, warm light",
  "aspect_ratio": "1:1",
  "quality": "auto"
}
  • prompt — 必填,文本提示词。
  • aspect_ratio — 可选,仅支持 1:1 / 2:3 / 3:2,默认 1:1。
  • quality — 可选,默认 auto;每张固定扣 20 credits。

成功响应 · 202

{
  "success": true,
  "data": {
    "id": "f0c2e7a0-...",
    "status": "queued",
    "aspect_ratio": "1:1",
    "images": [],
    "error": null,
    "estimated_credits": 20,
    "charged_credits": 20,
    "poll_url": "/v1/images/jobs/f0c2e7a0-...",
    "created_at": "2026-05-29T00:00:00.000Z",
    "updated_at": null
  },
  "request_id": "uuid"
}
创建响应里的 charged_credits: 20 表示本次已冻结的额度。轮询查询时,charged_credits 只有在任务成功结算后才会变为实际扣费;进行中、失败或超时为 0,冻结额度始终体现在 estimated_credits。

cURL 示例

curl -X POST https://your-host/v1/images/generations \
  -H "content-type: application/json" \
  -H "Authorization: Bearer gim_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" \
  -d '{"prompt":"a cozy cabin in the snow","aspect_ratio":"1:1","quality":"auto"}'

04查询任务

GET /v1/images/jobs/:id

轮询任务状态。只能查询自己创建的任务;查询不属于自己的任务或不存在的 id,一律返回 404 job_not_found。

成功响应 · 200

{
  "success": true,
  "data": {
    "id": "f0c2e7a0-...",
    "status": "succeeded",
    "aspect_ratio": "1:1",
    "images": [
      { "url": "https://cdn.example.com/xxx.png", "b64_json": null, "local_url": null, "prompt": "..." }
    ],
    "error": null,
    "estimated_credits": 20,
    "charged_credits": 20,
    "created_at": "2026-05-29T00:00:00.000Z",
    "updated_at": "2026-05-29T00:00:12.000Z"
  },
  "request_id": "uuid"
}
  • status — queued / processing / succeeded / failed 等。
  • images — 成功后才有内容,每项含 url、b64_json、local_url、prompt。
  • error — 失败时为错误信息,否则为 null。
  • charged_credits — 成功结算后才是实际扣费;进行中、失败或超时为 0。

cURL 示例

curl https://your-host/v1/images/jobs/f0c2e7a0-... \
  -H "Authorization: Bearer gim_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"

05错误码

所有错误响应统一为 { "success": false, "error": { "code", "message", "details" }, "request_id" }。

HTTPcode含义
400invalid_promptprompt 缺失或不是字符串
400prompt_too_longprompt 超过长度上限
400invalid_aspect_ratio比例不在 1:1 / 2:3 / 3:2 之内
401unauthorized缺失/无效 Key,或 Key、账户被禁用
402insufficient_credits余额不足,details 含 required / available
409api_concurrency_limited已有未完成任务(默认同时 1 个)
429rate_limited超过频率限制(默认每分钟 5 次)
关于 401:无论缺 Key、Key 无效,还是 Key/账户被禁用,统一返回 401,不用 403 区分,避免泄露账户状态细节。

06限流与并发

  • 频率限制 — 默认每个 Key 每分钟最多 5 次请求,超出返回 429 rate_limited。
  • 并发限制 — 默认每个账户同时最多 1 个未完成任务,已有任务在跑时再创建返回 409 api_concurrency_limited。
  • 建议轮询间隔 ≥ 1s,任务完成(succeeded / failed)后即可发起下一个。
